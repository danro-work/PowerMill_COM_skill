# СС, конвертация, PP и порядок

В изученных проектах Stok — исходные, ADD+sort — конвертированные/сортированные,
PP — с назначенными PP, SIM — подготовленные для симуляции. Это соглашение
проекта, не типы API. P обозначает часть проекта. Сперва читай реальную структуру.

Для импорта используй именно указанный пользователем макрос и его версию.
Сначала прочитай файл макроса и его входы; одноимённый старый макрос не
подтверждает совместимость с текущей версией.
При импорте и расчёте явно задай `Tolerance` по текущему заданию и инструкциям
проекта. Не оставляй унаследованное значение стратегии без проверки: допуск
влияет на число точек и должен быть подтверждён до `CALCULATE`.
Путь макросов и исходных контуров получай для текущего компьютера. При заданном
разделении «Контура 0», «Контура 1», ... создавай соответствующие папки P0,
P1, ...; сверяй перечень импортированных шаблонов/траекторий с файлами, не
импортируй повторно уже выполненные позиции при возобновлении.

## Пакетные СС

Полная выгрузка рабочих полилиний → пересечение лучом → циклическая
перестановка вершин с разделением одной стороны → импорт PIC → штатный расчёт
траектории и связей. Геометрия целиком не поворачивается. Проверенная область:
замкнутые XY-полилинии до PP, оси +Z, нулевые векторы ориентации. Другие оси,
неплоские/открытые кривые и существующие PP требуют сохраняющей данные адаптации.

PIC: формат Autodesk PicWriter, фиксированные поля заголовка, CRLF,
экспонента E±ddd. Старый writer с произвольной scientific-записью дал пустой
нативный импорт, хотя Python round-trip проходил. Локальный round-trip
не доказывает успешный импорт PowerMill.

Углы задаются по задаче; счётчик может сбрасываться для каждой исходной
траектории. Минимум СС проверять по реальным ближайшим точкам в каждом слое.
На открытых проходах уточнять зигзаг или одно направление по текущему заданию.

Проверка: число проходов, замкнутость/направление, сохранность вершин,
полное геометрическое отклонение, оси, СС, переходы.
Connections.MoveStartPoints=0 сохраняет подготовленные СС при расчёте связей.
Касающиеся кривые PIC могут склеиваться при одном INSERT FILE; отдельные
порции сохраняли границы. Проверять выделение и число проходов до расчёта.

## Конвертация

На копиях; тип базы, поверхность/слой и шаг задаёт задание. Для плоскости Z=0
нужна фактическая база, одного числа 0 недостаточно. Для произвольной базы
задаётся соответствующий слой/набор. Проверять ManufacturingProcess, Computed,
реальные слои, число проходов, геометрию и оси до назначения PP.

## Нумерация и рецепты PP

Согласованная таблица процесса:

| Тип | Диапазон |
| --- | --- |
| FeedRate | 20–39 |
| CNT_Loff | 40–59 |
| CNT_Lon | 60–79 |
| LaserPower | 80–99 |
| Speed | 100–119 |
| Wait | 120–129 |

Это номера параметров процесса, не физические мощности/подачи. Роли и значения
для P задаются отдельно. Для CNT различать Loff/Lon.

Проверенный PointParameterMethod для LP:
ParameterKey=udp_LaserPower, Location=repeated, Reference=component,
ComponentType=segment, Position=from_start, Distance=0, Value — LP задачи.
Сначала подготовить все правила, затем один METHODS APPLY. Сохранять
существующие рецепты и остальные PP: индекс добавления читать, не принимать
за 0. Поштучное назначение — для исключений.

Для CNT_Loff изученный фактический ключ — udp_CNT_OFF; положение и Distance
задаёт текущее задание. Короткие двухточечные проходы требуют проверки PP
и геометрии.
CNT_Lon не считать проверенным по аналогии: прочитать фактический ключ.

Проверять point_parameters до/после объединения, после удаления методов,
если оно входит в задание. Рецепт в форме не доказывает PP в точках.
Большую геометрию и PP читать раздельными массивами, связывать по индексам
и проверенным количествам. Выборку не выдавать за полный аудит.

## Оси, порядок, связи

ToolAxis.Type=to_line для PatternFinishing здесь дал реальные оси наружу.
Судить по переводу from_line/to_line нельзя: сверять XYZ и ToolAxis.
Порядок closed/open, ролей, пар стенки, рёбер и массивы задаёт задача.

### Порядок аддитивных валиков по геометрии

Базовая логика пользователя для новой подготовки; конкретная геометрия и
технология могут требовать исключений, а явные указания текущего задания
имеют приоритет:

- Поддержку, создающую базу для последующих валиков слоя, выполняй первой.
- Определяй очередь по геометрической роли валиков в областях слоя:
  внутренние границы → заполнение → наружные границы. Сохраняй движение
  изнутри наружу; не определяй порядок только по имени шаблона или
  замкнутости. Если одна траектория содержит границы с разными ролями,
  при необходимости разделяй её для размещения частей до и после заполнения.
- При перестановке сохраняй назначенные ПП соответствующих валиков:
  новая позиция в очереди сама по себе не меняет LP или CNT.
- Это правило планирования в рамках порученной подготовки; его сохранение
  не разрешает менять ранее готовые траектории без соответствующего задания.

Большая TPLIST медленная. Проверен вариант малых копий слоёв с последующим
штатным объединением. Для объединения входы в одной папке и точный список
выделения: Explorer снимал выделение объектов из другой папки. Сверять
идентичность проходов/количества и фактические PP.

Штатный расчёт связей: PROCESS TPLEADS. PROCESS TOOLPATH LEADS из старого
макроса в этой версии не поддерживалась. segment_get_point не предоставлял
промежуточную геометрию lead/link; счётчики/PP не считать полным аудитом связей.

## Измерения и пределы переноса

Время пакетных СС, PP и сортировки зависит от размера и структуры текущего
проекта. Отдельно измеряй подготовку, нативный расчёт, COM-чтение и ожидание;
выборку и её охват указывай в отчёте. Офлайн-выигрыш планировщика не доказывает
ускорение живой операции в PowerMill.
